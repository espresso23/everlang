# Korean device TTS — canonical client contract

Source [apps/web/lib/korean-audio.ts](../../apps/web/lib/korean-audio.ts), symbols playKorean/stopKorean. Consumers: vocabulary-catalog word/example and vocabulary-srs review. No provider key/download/output storage, no audio assessment. Platform voice can be local or network depending browser/OS; do not promise offline or professionally reviewed audio.

playKorean(text) returns Promise<void>: checks speechSynthesis, waits up to800ms for voiceschanged, requires voice language ko/ko-KR (BCP47 variants); cancels prior utterance, speaks at0.88 rate. Unsupported/no voice/error returns Vietnamese guidance to caller. Completion or explicit canceled/interrupted settles without error;30s timeout rejects then cancels. Coordinator generation + active cancellation settle old promises/clear old timers even if native cancel emits no event; stopKorean invalidates pending voice lookup and stops current audio. Callers catch errors near listen action and use stopKorean on unmount/card advance; no silent choice of a non-Korean voice. A finished promise is not proof physical audio was heard or the voice is linguistically correct. Hardware/voice QA remains a gate, curated samples PB-036 separate.

SRS recall uses catalogue snapshot KO/VI to hide generated Vietnamese translation until explicit reveal; see [catalog functions](../features/vocabulary-catalog/functions.md), not TTS scoring. Personal custom contexts retained.
