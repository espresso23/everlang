## Kiểm tra, rollback và review

- Bug/logic: TDD hành vi red → green; nội dung/docs: review nguồn, ngôn ngữ và link, TDD N/A. Mọi thay đổi code cần lint/typecheck/build và unit/integration/E2E phù hợp.
- Demo success và failure bằng tài khoản QA cô lập; kiểm UI → auth → API → PostgreSQL → phản hồi; worker/provider chỉ khi luồng dùng đến. Không dùng dữ liệu người học thật làm fixture.
- Schema/data change cần backup/restore và migration additive; giữ ID/revision/lịch sử. Nội dung published chỉ sửa qua revision mới; rollback không DROP hay reset dữ liệu.
- Self-review riêng sau implementation; audit ghi PASS/FAIL/NOT VERIFIED, commit/lệnh/evidence; cập nhật HANDOFF và tracking rồi báo cáo DONE–DOING–NEXT.
- Theo chỉ định owner 2026-11-01: mỗi đầu việc phải có GitHub issue; xong và review đạt AC thì mark Done/close completed. Các acceptance cần người duyệt nội dung, thiết bị thật hoặc production go/no-go vẫn cần bằng chứng tương ứng; không tự chứng nhận.
